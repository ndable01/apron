# Apron: самостоятельное демо

Адрес опубликованного прототипа: https://ndable01.github.io/apron/
Существующий QR и адрес GitHub Pages сохраняются. Новые QR для ролей не нужны.

## Сценарий участника

1. Открыть существующий QR. Новая вкладка всегда начинает от лица поставщика, в том числе при старых параметрах `role` и `room`.
2. В пробе уже заданы 28 демонстрационных плодов с одним браком. Проверить два своих плода: Apron выбирает ящик, участник снимает плод.
3. Пока внешняя модель не подключена, отметить каждый снимок вручную. Источник результата явно указан. Никакой автоматической симуляции нет.
4. Нажать «Посмотреть со стороны РЦ». Здесь будут собственные снимки участника, счёт пробы, рекомендация, отчёт и решения РЦ.
5. При низком риске выбрать «Ждём машину». При заметном или высоком - «Вернуть на досортировку» либо «Ждём, приёмка усиленная». Вернуться к поставщику: ответ РЦ уже виден.

Каждая вкладка хранит собственную пробу в `sessionStorage`. Перезагрузка её сохраняет; закрытие вкладки завершает сеанс. Между участниками нет общей комнаты, обмена снимками и решений. Параметр `room` из старых ссылок игнорируется. Экран зала не используется.

## Развилки

- Два годных: 1 брак из 30, расчётный риск около 10 %.
- Один новый брак: 2 из 30, риск около 29 %. Можно досортировать либо расширить пробу ещё на 10 годных плодов; тогда риск станет ниже 15 %.
- «Не по критериям» учитывается отдельно. Основной счёт переключается на категорию, у которой риск выше.
- «Не согласен» и исправление в отчёте заменяют прежний результат без двойного подсчёта. Прежнее решение РЦ сбрасывается и требует повторного выбора.
- Неудачный кадр, не томат и низкая уверенность предусмотрены в контракте будущего API. Неудачные снимки не увеличивают счётчик, выбранный ящик сохраняется.

## Сброс и проверка

Кнопка «Начать заново»/«Пройти заново» сбрасывает только эту вкладку после подтверждения.

`?demo=1`: удерживать Apron две секунды (с клавиатуры Enter или пробел), чтобы открыть настройки. Там доступен «Тест без камеры»: встроенное фото, ручной вердикт, заметная пометка «тест» во всех результатах. Выбора подставного ответа модели нет.

`?selftest=1`: контрольные расчёты на экране и в консоли.

Локально: `python3 -m http.server 8000 --bind 127.0.0.1`, открыть http://127.0.0.1:8000/.
Проверки логики: `node --test tests/core.test.cjs`.

## Без интернета

Сначала открыть страницу с интернетом и дождаться загрузки. Service worker сохраняет страницу, скрипты, шрифты и тестовое фото для повторного открытия без сети. Если браузер запрещает service worker, офлайн-перезагрузка недоступна; уже открытая страница продолжает работать.

После загрузки сценарий и ручная отметка не требуют внешних сервисов. Если видоискатель недоступен, появляется «Снять системной камерой». По HTTP на телефоне видоискатель может быть запрещён; GitHub Pages использует HTTPS.

Для запасного показа заранее открыть страницу на телефоне команды и ноутбуке. Подготовить запись прогона, если площадка не позволяет открыть сам сайт.

## Что является демонстрацией

Допуски по 10 %, пороги риска 15/25 %, сумма 1,2 млн ₽, рейс, названия, слот РЦ, документы, приборные замеры и исходные 28 плодов - демонстрационные параметры `ApronCore.CONFIG` в `assets/core.js`. Изображений стартовой пробы пока нет, фотографии не подменяются.

Риск: для каждой категории отдельно используется Beta(k + 0,5; n - k + 0,5), считается вероятность превышения допуска. Общий показатель - максимум двух рисков, не вероятность любого нарушения. Нужны случайный отбор и независимые наблюдения. Ошибки модели и ухудшение качества в дороге в расчёт не включены. Интервал Уилсона показывает неопределённость по доле брака. Это не обещание окончательной приёмки.

## Следующий этап: внешняя модель

Оригиналы `prompts/inspect-system.md` и `prompts/inspect-schema.json` сохранены без изменений. Ключа и работающего relay в этой версии нет.

После выбора провайдера отдельно размещается relay. Клиент готов отправлять `POST { image, spec, context: { expected_box, fruit } }`, где `image` - JPEG до 1024 px по длинной стороне. Ожидается `{ ok: true, result, model, ms }`; `result` соответствует схеме. Таймаут клиента - 10 секунд, уверенность ниже 0,7 требует ручной отметки. Все тексты ответа выводятся как текст, не HTML. Ключ хранится только в секретах relay. `CONFIG.analyzeUrl` задаёт адрес сервиса, не ключ.

Перед подключением сверить нормативные утверждения в системнике с первоисточником, проверить достаточность лимита ответа для восьми критериев и установить единый бюджет таймаута с учётом повторов. Реальные правила сети передаются в `chain_rules`; сейчас список пуст.

## За час до показа

- Открыть прежний QR на iPhone Safari и Android Chrome, проверить камеру.
- Проверить две отметки, переход к РЦ, отчёт, все доступные решения и возврат к поставщику.
- Проверить изменение отметки и сброс решения, расширение пробы, перезагрузку.
- Открыть все нужные страницы заранее для офлайн-кэша.
- Сбросить пробу на телефоне команды. Убедиться, что старт - 28 из 30.
- После подключения модели отдельно измерить качество и скорость на размеченных фото. До этого не заявлять измеренную точность и время ответа.
